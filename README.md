  **외부 오리진 요청이 0건**입니다. 93개 서브셋 중 화면에 실제로 쓰인 글자가

- **짙은 면은 상세 페이지 맨 아래 CTA 에만.** 홈은 흰 바탕으로 통일합니다.
- **그림자는 카드에만, 그것도 오른쪽·아래에만.** 사방으로 퍼지는 그림자는
  촌스러워서 `12px 12px 24px -10px` 로 **오프셋 > 번짐** 이 되게 잡았습니다.
  음수 spread 가 그림자를 안쪽으로 줄여 위·왼쪽으로는 한 톨도 새지 않습니다
  (값을 바꿀 때 `offset - |spread| ≥ blur/2` 를 지키세요).
  카드 모서리는 `rounded-3xl`, 그 밖의 구분은 전부 헤어라인과 여백으로 합니다.
- **헤더 바탕은 순백(`bg-white`).** 로고 두 개가 흰 배경을 가진 그림이라,
  바탕에 한 톨이라도 회색기가 돌면(`page` 는 `#FCFCFD`) 로고 자리만 밝은
  사각형으로 떠 보입니다. 여기만 `page` 대신 순백을 씁니다.
- **움직임은 사용자가 시킨 것만.** 히어로는 휠, 카드는 화살표.
  `prefers-reduced-motion` 시 전부 꺼지거나 즉시 건너뜁니다.

## 히어로 — 가운데에서 번지는 배경 영상

`src/components/HeroReveal.tsx`

영상은 **처음부터 화면 전체 크기**로 깔려 있습니다. 마스크(`mask-image` 의 타원형
radial-gradient)로 가운데 인물 주변만 또렷하게 두고 바깥은 **페이지 바탕색**으로 덮어
두었다가, 페이지가 뜨면 0.4초 멈췄다 1.8초에 걸쳐 **저절로** 넓혀 갑니다. 넓어지는
가장자리는 마스크의 그라데이션을 지나면서 희미한 상태에서 점점 진해집니다.

**스크롤과는 아무 상관이 없습니다.** 스크롤을 막지 않고, 보는 사람이 그 사이 아래로
내려가 버려도 연출은 알아서 끝까지 갑니다.

크기가 변하는 요소가 없으므로 **레이아웃은 처음부터 끝까지 그대로**입니다. 제목·본문·
전화 버튼도 첫 프레임부터 제자리에 있고 색도 변하지 않습니다.

### 글자가 계속 읽히게 하는 방법

글자가 얹히는 아래쪽에는 **바탕색 그라데이션을 항상** 깔아 둡니다. 번지기 전에는
어차피 그 자리가 바탕색이라 이 층이 보이지 않고, 다 번진 뒤에만 영상 위에 드러나
먹색 글자를 그대로 읽히게 합니다.

글자색을 먹색↔흰색으로 건너가게 하는 방법은 **쓰지 않았습니다.** 배경도 밝음→어두움,
글자도 어두움→밝음으로 같이 움직이면 중간 어딘가에서 두 색이 반드시 만나 글자가
사라집니다. 두 램프를 어긋나게 잡아도 교차 구간의 대비가 3:1 아래로 떨어집니다.

`public/video/hero.mp4` — H.264 High@3.1, 1280×720, 8초, 1.9MB.
포스터는 `public/photos/hero-poster.jpg` (영상의 원본 프레임, 동일한 1280×720).

### 워터마크 잘라내기

영상 오른쪽 위에 제작 도구 워터마크가 8초 내내 박혀 있습니다
(원본 1280×720 기준 **x 1079~1244, y 35~58**). 영상 파일에서 지울 방법이 없어
**위쪽 11%(79px)를 잘라 냅니다.** 잘라낸 만큼 세로로 키우고(`112.36%`) 그만큼
끌어올려(`top: -12.36%`) 아래 끝을 화면 아래 끝에 맞춥니다. `object-fit: cover` 가
어떤 화면비에서도 최소 11% 는 더 잘라 내므로 워터마크가 다시 나올 일은 없습니다.

대신 인물의 **정수리 쪽이 함께 잘립니다.** 워터마크가 없는 영상으로 교체하면
`CROP_TOP` 을 `0` 으로 두는 편이 낫습니다.

### 결정한 것들

| 항목 | 선택 | 이유 |
| --- | --- | --- |
| 애니메이션 라이브러리 | 쓰지 않음 (인라인 스타일로 값 보간) | 하는 일이 값 보간 하나뿐이라 100KB를 더할 이유가 없음 |
| 진행 | 페이지 진입 직후 자동 (1.8초) | 전화번호를 찾으러 온 사람을 가두지 않기 위해 |
| 스크롤 잠금 | 하지 않음 | 스크롤을 가로채면 찾아 온 목적을 방해합니다 |
| 기준 시각 | 마운트 시점이 아니라 **첫 rAF 프레임** | 백그라운드 탭에서는 rAF 가 멈춰, 마운트 기준이면 탭으로 돌아왔을 때 연출이 통째로 생략됨 |
| `prefers-reduced-motion` | `globals.css` 의 `.hero-reveal` 에서 마스크를 끔 | CSS 가 JS 보다 먼저 적용되므로 한 프레임도 번지지 않음 |
| 마스크 시작 크기 | 인물이 또렷한 영역 안에 통째로 들어가는 크기 | 인물이 잘린 채 시작하면 무엇이 번지는지 읽히지 않음 |

영상은 **항상 음소거**입니다. 브라우저가 음소거 아닌 자동재생을 막기도 하고,
병원 사이트에서 소리가 나는 것은 사고에 가깝습니다.

> **최적화 권장** — 현재 `moov` 아톰이 파일 끝에 있어 브라우저가 1.9MB를 모두 받은 뒤에야
> 재생을 시작합니다. ffmpeg 로 앞으로 옮기면 즉시 시작됩니다(재인코딩 없음):
>
> ```bash
> ffmpeg -i public/video/hero.mp4 -c copy -movflags +faststart public/video/hero-fast.mp4
> ```
>
> ffmpeg 가 있다면 워터마크도 CSS 가 아니라 영상에서 직접 잘라 내는 편이 낫습니다.
> 그러면 `CROP_TOP` 을 `0` 으로 되돌려 정수리를 살릴 수 있습니다:
>
> ```bash
> ffmpeg -i public/video/hero.mp4 -vf "crop=1280:641:0:79" -movflags +faststart public/video/hero-cropped.mp4
> ```

## 카드 넘기기 — 임플란트 · 교정

`src/components/CardCarousel.tsx`

**임플란트 · 치아교정 · 병원 둘러보기** 세 덩이가 이 방식입니다. 진료 원칙은 여섯
가지를 한눈에 보는 편이 나아 카드 그리드로 그냥 펼쳐 둡니다.

`CardRail`(`src/components/CardRail.tsx`)이 셋의 짜임을 함께 씁니다. 왼쪽 기둥에
제목·안내와 **항목 이름 목록**, 오른쪽에 카드. 이름을 누르면 그 카드로 넘어가고,
반대로 화살표나 손가락으로 카드를 넘기면 왼쪽 표시가 따라옵니다. 두 쪽이 같은
번호 하나를 보므로 어느 쪽으로 조작해도 어긋나지 않습니다.

카드 좌우의 동그란 화살표를 누르면 옆 카드로 부드럽게 넘어갑니다. 좁은
화면(<640px)에서는 좌우에 화살표를 둘 자리가 없어 카드 아래로 내립니다.

상세 페이지로 가는 "더 보기" 링크는 이 목록으로 대신했고, `/implant`·`/ortho` 는
헤더 메뉴로 들어갑니다.

`lead` 는 제목 **옆**에 붙는 짧은 부가 설명입니다("위 어금니 뼈가 부족할 때").
윗줄에 따로 세우면 카드가 그만큼 길어집니다. 교정은 한 줄 요약(`summary`)이
이 자리에 들어갑니다.

카드 안에서는 `prose-ko`(행간 1.9)를 쓰지 않습니다. 카드가 세로로 너무 길어져서
`leading-[1.6]` 으로 조입니다. 글과 그림 사이에는 괘선을 두지 않고, **그림이 아직
없는 항목도 그림 자리를 그대로 비워 둡니다** — 안 그러면 카드끼리 짜임이 어긋납니다.

카드는 **한 번에 한 장**만 보입니다. 흰 바탕에 그림자로 경계를 만들고,
`.card-shell` 이 **6:4(가로가 긴) 비율을 바닥으로** 잡습니다. 시술 카드는 위쪽에
설명, 아래쪽에 시술 그림이 눕습니다. 도해는 잘리면 뜻이 달라지므로
`object-contain` 으로 통째로 보여 줍니다.

둘러보기 사진도 같은 비율로 잘라 맞춥니다(`object-cover`). 사진 원래 비율을 그대로
쓰는 `ownRatio` 옵션이 남아 있지만 지금은 쓰지 않습니다 — 카드 높이가 장마다
달라져 넘길 때 들쭉날쭉했습니다.

> **`aspect-ratio` + `min-height: fit-content` 로 되돌리지 마세요.** 크롬이 이 조합에서
> 비율을 상한처럼 다뤄, 항목이 다섯 개인 교정 카드의 글이 잘려 나갔습니다
> (`scrollHeight 454 > clientHeight 432`). 지금은 **높이만 만드는 지지대**
> (`.card-ratio`, `padding-top: 150%`)를 카드 안에 깔고 내용과 같은 그리드 칸에
> 겹쳐 둡니다. 칸 높이는 둘 중 큰 쪽을 따르므로 짧은 글은 비율대로, 긴 글은 글
> 길이대로 자랍니다.

> **레일 안쪽 여백을 지우지 마세요.** 그림자는 레일의 `overflow-x` 에 잘립니다.
> `px-3 py-5` 로 자리를 만들고, 첫 장이 왼쪽 여백만큼 밀리지 않도록 `scroll-px-3`
> 으로 스냅 기준도 같이 옮겨 두었습니다. 화살표가 넘길 위치도 레일이 아니라
> **첫 카드** 기준으로 계산합니다.

화살표를 끄는 기준은 카드 번호가 아니라 **실제로 더 굴릴 수 있는지**입니다.
두 장씩 보이는 화면에서 번호만 보고 판단하면, 마지막 카드가 이미 보이는데도
눌러도 아무 일이 없는 화살표가 켜져 있게 됩니다.

`image` 를 넘기면 글 대신 사진이 카드를 꽉 채우고 캡션이 아래에 얹힙니다
(둘러보기가 이 방식입니다). 상세 페이지(`/implant`, `/ortho`)는 **처음부터 전부
읽으러 오는 곳**이라 카드로 감추지 않고 그대로 나열합니다.

직접 위치를 계산해 `transform` 을 거는 대신 **네이티브 가로 스크롤 + scroll-snap**
위에 화살표를 얹었습니다. 그래야 손가락으로 쓸어 넘기기, 트랙패드 두 손가락 밀기,
키보드 좌우 키가 코드 없이 그대로 동작하고 화면 폭이 바뀌어도 위치가 어긋나지
않습니다. 화살표는 `rail.scrollTo()` 를 부를 뿐입니다.

### 덜컹거리지 않게

`globals.css` 의 `html { scrollbar-gutter: stable }` 을 지우지 마세요. 스크롤바가
생겼다 없어질 때마다 화면 너비가 15px 달라지는데, 그러면 화면을 꽉 채운 히어로
배경 영상까지 통째로 다시 배치되면서 한 번 덜컹합니다.

> **`behavior` 를 생략하지 마세요.** `scrollTo({ left })` 만 쓰면 CSS 의
> `scroll-behavior: smooth` 를 따라야 하는데, 버튼 클릭 안에서 부를 때 넘어가지
> 않는 경우가 있습니다. `behavior: "smooth"` 를 명시하고, 움직임 최소화 설정일
> 때만 `"auto"` 로 바꿉니다.

스크롤바는 감추고(`.card-rail`) 화살표와 "2 / 5" 표시로 대신합니다. 감춘 만큼
목록 자체에 `tabIndex=0` 을 두어 키보드로도 스크롤할 수 있게 했습니다.

## 바탕색과 지도

- **의료진까지는 흰 바탕.** 짙거나 회색 면은 **자주 묻는 질문 · 진료시간 · 푸터**
  에만 씁니다. 페이지 아래쪽으로 갈수록 한 톤 내려앉는 짜임입니다.
- **지도는 `src/components/NaverMap.tsx`** 입니다. `map.naver.com` 은
  `X-Frame-Options` 로 iframe 을 막아 두어 주소만 넣어 퍼오는 방법이 없습니다.
  화면 안에 지도를 띄우려면 **네이버 지도 JavaScript API v3** 뿐이고, 네이버
  클라우드 플랫폼 Client ID 가 필요합니다 (`.env.example` 에 발급 절차).
  키가 없거나 지도를 못 불러오면 네이버 지도로 넘겨 주는 링크로 물러섭니다.
  좌표는 박아 넣지 않고 **Geocoding 으로 `clinic.address` 에서 찾습니다.**
  손으로 적어 두면 주소를 고칠 때 표식만 엉뚱한 자리에 남습니다.
  (링크 대체용 `clinic.mapUrl` 은 `address` 를 고칠 때 같이 고쳐야 합니다.)
- **푸터에는 진료시간·오시는 길을 적지 않습니다.** 바로 위 섹션에 이미 있어서
  두 군데를 같이 고쳐야 하는 자리가 생깁니다.
